1. 퍼징이란 무엇이며, 어떤 종류가 있는지

퍼징은 대상 프로그램에 예상치 못한 무작위, 변형 입력값을 대량으로 주입한 뒤, 프로그램이 비정상 종료, 메모리 손상, 무한 루프, 예외 등을 일으키는지 관찰하여 보안 취약점이나 버그를 자동으로 찾아내는 동적 소프트웨어 테스트 기법이다.

퍼징을 분류하는 기준엔 입력값 생성 방식, 내부 코드 정보 활용도 두가지가 있다.

1) 입력값 생성 방식에 따른 분류
-변이 기반: 정상적인 입력 파일을 준비한 뒤, 비트 뒤집기, 바이트 삽입 삭제 치환 등으로 조금씩 변형해 입력한다. 구현이 쉽고 범용적이지만, 입력 구조가 복잡하면 초기 검증 단계를 통과하기 어려움.

-생성 기반: 프로토콜 명세나 파일 포맷 문법을 미리 정의해두고, 그 규칙에 맞춰 입력값을 처음부터 새로 생성한다. 복잡한 파서 깁숙한 곳까지 도달하기 유리하지만, 명세를 작성하는 데  시간과 노력이 많이 듬.

2) 내부 정보 활용도에 따른 분류

-블랙박스

내부 정보 활용: 없음

동작 방식: 입력과 출력만 관찰

장단점: 설정이 매우 간단하지만, 코드 깊숙한 경로 탐색에 한계가 있음.

-그레이박스

내부 정보 활용: 일부 활용(코드 커버리지)

동작 방식: 바이너리에 instrument를 삽입해 새로운 코드 경로를 발견한 입력을 우선 변이

장단점: 현재 가장 널리 쓰이고 있는 방식이며 속도와 탐색 효율의 균형이 좋음.

-화이트박스

내부 정보 활용: 전체 활용(소스/실행 경로)

동작 방식: 기호 실행, 오염 분석 등으로 조건문을 수학적으로 풀어 입력 생성

장단점: 복잡한 조건문을 통과해 깊은 버그를 찾지만, 연산 비용이 크고 속도가 매우 느림.

2. 주요 퍼저의 종류와 차이점

-AFL/AFL++

기반 방식: 그레이박스(변이 기반)

주요 대상: 바이너리, 파일 파서

핵심 특징 및 차이점: 커버리지 기반 퍼징의 표준임. AFL++는 기존 AFL을 계승해서 속도,변이 전략, 커스텀 뮤테이터 지원 등을 강화한 현대적 표준 도구임.

-libFuzzer

기반 방식: 그레이박스(in process)

주요 대상: 라이브러리, 특정 함수 단위

핵심 특징 및 차이점: LLVM/Clang에 내장돼있음. 프로세스를 매번 새로 띄우지 않고 메모리 내에서 함수를 반복 호출해서 실행 속도가 빠름.

-Honggfuzz

기반 방식: 그레이박스

주요 대상: 바이너리, 네트워크, 커널

핵심 특징 및 차이점: 구글에서 개발함. 하드웨어 기반 피드백이랑 멀티스레드 지원이 강하고 크래시분석 과 안정성이 뛰어남.

-Boofuzz

기반 방식: 블랙박스(생성 기반)

주요 대상: 네트워크 프로토콜

핵심 특징 및 차이점: 과거 유명했던 Sulley의 후속작임. 파이썬으로 프로토콜 패킷 구조를 정의해서 테스트하고 네트워크 장비나 서버 퍼징에 특화돼있음.

-Syzkaller

기반 방식: 그레이박스(생성+ 변이)

주요 대상: OS 커널

핵심 특징 및 차이점: 구글에서 개발한 커널 전용 퍼저임. 시스템 콜 시퀀스를 문법에 맞게 생성하고 커버리지를 추적해서 커널 취약점을 발굴함.

핵심 차이점


1) 프로세스 실행 방식의 차이: AFL++는 기본적으로 forkserver를 사용해 별도 프로세스로 대상을 실행하지만, libFuzzer는 대상 함수에 직접 링크돼서 같은 프로세스 안에서 돔. 그래서 단일 함수랑 라이브러리 테스트는 libFuzzer, 독립 실행 파일은 AFL++가 유리함.


2) 타겟 도메인의 차이: 파일 입력을 받는 일반 프로그램은 AFL++/libFuzzer, 패킷을 주고받는 네트워크 서버는 Boofuzz, 운영체제 커널은 Syzkaller처럼 대상의 입력 인터페이스에 따라서 퍼저를 선택함.
